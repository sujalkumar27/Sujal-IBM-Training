1. What is Docker?

Docker is an open-source platform for developing, shipping, and running applications inside lightweight, portable containers.

Key Concepts:

  • Container: A runnable instance of an image — isolated process with its own filesystem.
  • Image: A read-only template with instructions to create a container.
  • Docker Engine: Client-server application (daemon + REST API + CLI).
  • Docker Hub: Cloud-based registry to share images.
💡 Containers vs VMs: Containers share the host OS kernel; VMs run a full guest OS. Containers are lighter, faster, and more portable.

2. Docker Architecture

  • Docker Client (CLI): Sends commands to the daemon (docker command).
  • Docker Daemon (dockerd): Manages Docker objects — images, containers, networks, volumes.
  • Docker Registry: Stores Docker images (Docker Hub is the default public registry).
  • Docker Objects: Images, Containers, Networks, Volumes, Plugins.

Docker uses REST API over UNIX sockets or a network interface for client-daemon communication.

4. Docker Images

An image is a read-only template used to create containers. Built in layers.

Image Commands:

docker pull <image>              # Download image from registry
docker images                    # List local images
docker rmi <image>               # Remove an image
docker image prune               # Remove dangling images
docker build -t myapp:1.0 .      # Build image from Dockerfile
docker tag myapp:1.0 user/myapp  # Tag an image
docker history <image>           # Show image layers
docker inspect <image>           # Detailed image info
docker save -o file.tar <image> # Export image
docker load -i file.tar          # Import image
💡 Image tags follow the format repository:tag. If no tag is specified, latest is used.

5. Containers

Lifecycle Commands:

docker run <image>               # Create + start container
docker run -d nginx              # Detached mode
docker run -it ubuntu bash       # Interactive terminal
docker run -p 8080:80 nginx      # Port mapping
docker run --name web nginx      # Custom name
docker run -e ENV=prod nginx     # Environment variables

docker ps                        # Running containers
docker ps -a                     # All containers
docker start <id>                # Start a stopped container
docker stop <id>                 # Graceful stop
docker restart <id>              # Restart
docker kill <id>                 # Force stop (SIGKILL)
docker rm <id>                   # Remove container
docker rm -f <id>                # Force remove

docker exec -it <id> bash        # Enter running container
docker logs <id>                 # View logs
docker logs -f <id>              # Follow logs
docker stats                     # Live resource usage
docker top <id>                  # Running processes
docker inspect <id>              # Detailed info
docker cp file.txt <id>:/path    # Copy to container

Common Run Flags:

FlagDescription
-dDetached (background)
-itInteractive + TTY
-p host:containerPort mapping
-v host:containerVolume mount
-e KEY=VALEnvironment variable
--nameAssign name
--rmAuto-remove on exit
--networkConnect to network
--restartRestart policy (no, always, on-failure)

6. Dockerfile

A Dockerfile is a text file with instructions to build a Docker image.

Common Instructions:

InstructionPurpose
FROMBase image (must be first)
LABELMetadata
WORKDIRSet working directory
COPYCopy files from host to image
ADDCopy + supports URLs and auto-extract
RUNExecute command at build time
CMDDefault command (only one, overridable)
ENTRYPOINTMain executable (not easily overridden)
ENVEnvironment variable
EXPOSEDocument ports
VOLUMECreate mount point
ARGBuild-time variables
USERSet user for RUN/CMD
HEALTHCHECKContainer health test

Example Dockerfile:

FROM node:18-alpine
WORKDIR /app
COPY package*.json ./
RUN npm install
COPY . .
EXPOSE 3000
CMD ["node", "server.js"]
💡 CMD vs ENTRYPOINT: CMD provides defaults that can be overridden; ENTRYPOINT defines the command that always runs.

7. Volumes & Storage

Docker offers three ways to persist data:

  • Volumes: Managed by Docker in /var/lib/docker/volumes/ — preferred.
  • Bind Mounts: Map host directory into container.
  • tmpfs Mounts: Stored in host memory only.

Volume Commands:

docker volume create myvol
docker volume ls
docker volume inspect myvol
docker volume rm myvol
docker volume prune

# Mount volume
docker run -v myvol:/data nginx
docker run --mount source=myvol,target=/data nginx

# Bind mount
docker run -v /host/path:/container/path nginx

9. Docker Compose

Docker Compose is a tool for defining and running multi-container applications using a YAML file (docker-compose.yml).

Example docker-compose.yml:

version: '3.8'
services:
  web:
    image: nginx
    ports:
      - "8080:80"
    depends_on:
      - db
  db:
    image: mysql:8
    environment:
      MYSQL_ROOT_PASSWORD: secret
    volumes:
      - dbdata:/var/lib/mysql
volumes:
  dbdata:

Compose Commands:

docker compose up            # Start services
docker compose up -d         # Detached
docker compose down          # Stop and remove
docker compose ps            # List services
docker compose logs          # View logs
docker compose build         # Build services
docker compose restart       # Restart services
docker compose exec <svc> bash

10. Registry & Docker Hub

11. Docker Swarm (Orchestration)

Docker's built-in orchestrator for managing a cluster of Docker nodes.

docker swarm init                          # Initialize swarm
docker swarm join --token <tok> <ip>       # Join swarm
docker node ls                             # List nodes
docker service create --name web nginx     # Create service
docker service ls
docker service scale web=5
docker service ps web
docker stack deploy -c compose.yml mystack # Deploy stack
docker swarm leave --force

Key terms: Manager node, Worker node, Service, Task, Stack.

12. Best Practices

  • Use official base images from trusted sources.
  • Use small base images like alpine to reduce size.
  • Leverage multi-stage builds to keep final images lean.
  • Use .dockerignore to exclude unnecessary files.
  • Combine RUN commands using && to reduce layers.
  • Never store secrets in images — use environment variables or Docker secrets.
  • Use specific tags, not latest, in production.
  • Run containers as non-root users.
  • Add HEALTHCHECK instructions in Dockerfiles.
  • Regularly scan images for vulnerabilities (e.g., docker scan).
⚠️ Avoid installing unnecessary packages — larger images = bigger attack surface.
